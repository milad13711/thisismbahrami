# دستورالعمل مهاجرت به قالب جدید (بدون آسیب سئو)

اصل: **اول روی استیجینگ، بعد روی سایت اصلی.** هر مرحله برگشت‌پذیر است.
مرجع سئو: `docs/baseline-live-2026-09-25.csv` (۵۲ آدرس). معیار عبور: `seo_snapshot.py --compare` بدون خطا.

## پیش‌نیازها
| مورد | مسئول | وضعیت |
|---|---|---|
| آدرس درست پنل DirectAdmin (https، از طریق IP/نام سرور؛ دامنه پشت آروان است) | میلاد | ⏳ |
| ورود به پنل و وردپرس (رمزها را فقط خود میلاد وارد می‌کند) | میلاد | ⏳ |
| خروجی Search Console (صفحات + کوئری‌ها، ۱۶ ماه) | میلاد | ⏳ |
| تست قالب روی وردپرس محلی (WordPress Playground با محتوای واقعی) | Claude | ✅ ۴۸/۵۲ آدرس سالم؛ ۳ آدرس دسته‌بندی به Rank Math وابسته‌اند |

## مرحله ۰ — نسخه‌ی پشتیبان کامل (سایت اصلی)
1. DirectAdmin → **Create/Restore Backups** → همه‌ی گزینه‌ها (Files + Databases + Email) → Create.
2. فایل پشتیبان را **دانلود** و خارج از سرور نگه دارید.
3. تا پایان مهاجرت، محتوای جدید منتشر نکنید.

## مرحله ۱ — ساخت استیجینگ
1. DirectAdmin → Subdomain Management → `staging` → پوشه‌ی `public_html/staging` (یا مسیر پیش‌فرض پنل).
2. آروان‌کلاد → DNS → رکورد `A` برای `staging` به **IP سرور اصلی**.
3. DirectAdmin → SSL Certificates → Let's Encrypt برای `staging.thisismbahrami.ir`.
4. DirectAdmin → Password Protected Directories → استیجینگ را رمزدار کنید (جلوی ایندکس و بازدید عمومی).
5. File Manager: همه‌ی فایل‌های `public_html` (به‌جز پوشه‌ی `staging`) را در پوشه‌ی استیجینگ کپی کنید.
6. MySQL Management → دیتابیس جدید `…_staging` + کاربر؛ phpMyAdmin → Export از دیتابیس اصلی → Import در دیتابیس استیجینگ.
7. `wp-config.php` استیجینگ: نام دیتابیس/کاربر/رمز جدید.
8. در دیتابیس استیجینگ آدرس سایت را عوض کنید (serialized-safe): افزونه‌ی موقت **Better Search Replace**:
   `https://thisismbahrami.ir` → `https://staging.thisismbahrami.ir` (همه‌ی جدول‌ها).
9. تنظیمات → خواندن → «از موتورهای جستجو بخواهید…» را **روشن** کنید (فقط استیجینگ).

## مرحله ۲ — مهاجرت روی استیجینگ
1. `theme/package.sh` → دو فایل `dist/milad-bahrami.zip` و `dist/mb-migration.zip`.
2. پیشخوان استیجینگ → پوسته‌ها → افزودن → بارگذاری `milad-bahrami.zip` (**فعلاً فعال نکنید**).
3. افزونه‌ها → بارگذاری `mb-migration.zip` → فعال‌سازی.
4. ابزارها → مهاجرت قالب → **دانلود خروجی المنتور** (المنتور هنوز فعال است).
5. تبدیل آفلاین با کنترل یکپارچگی (کلمه، تصویر، لینک):
   `python3 migration/elementor_to_html.py elementor-export.json cleaned.json`
   فقط اگر گزارش «0 need manual check» بود ادامه دهید.
6. ابزارها → مهاجرت قالب → **بارگذاری cleaned.json** (نسخه‌ی قبلی هر مطلب خودکار ذخیره می‌شود).
7. پوسته‌ها → فعال‌سازی **Milad Bahrami**.
8. ابزارها → مهاجرت قالب → **اعمال تنظیمات** (قالب صفحات، صفحه‌ی اصلی/وبلاگ، ساخت `/ارزیابی-سازمان/` و `/سلطان-قیف-فصل-اول/`، بازسازی پیوندها).
9. غیرفعال کردن: Elementor، Elementor Pro، Phlox Pro، Auxin Elements (و افزونه‌های auxin-*)، WP ULike.
   WooCommerce و Ultimate Member و افزونه‌ی رویدادها: فقط بعد از بررسی آمار Search Console (صفحات‌شان در sitemap نیستند، به‌جز رویدادها).
10. Rank Math → تنظیمات → پیوندها: «حذف پایه‌ی دسته‌بندی» **باید** روشن بماند؛ بدون آن ۳ آدرس دسته‌بندی baseline (`/توسعه-کسب-و-کار/` و …) 404 می‌شوند.
11. تنظیمات → پیوندهای یکتا → ذخیره (بدون تغییر) برای اطمینان.

## مرحله ۳ — آزمون استیجینگ (معیار عبور)
```bash
SNAPSHOT_AUTH=user:pass python3 scripts/seo_snapshot.py https://staging.thisismbahrami.ir docs/staging.csv --paths-from docs/baseline-live-2026-09-25.csv
python3 scripts/seo_snapshot.py --compare docs/baseline-live-2026-09-25.csv docs/staging.csv
```
- هر ۵۲ آدرس: 200 (یا 301 ثبت‌شده)، canonical یکسان (نسبت به دامنه)، فقط یک H1، بدون noindex ناخواسته.
- بازبینی چشمی: صفحه‌ی اصلی، مشاوره کسب‌وکار، درباره من، کتاب، ۵ مقاله‌ی پربازدید (طبق Search Console)، نمونه‌کارها، FAQ.
- فرم ارزیابی: یک درخواست آزمایشی → در پیشخوان «درخواست‌های ارزیابی» + ایمیل.

## مرحله ۴ — Rank Math (قبل از انتشار)
- **صفحه‌ی اصلی** (نامک `مشاور-کسب-و-کار-شیراز` — برای «مشاور کسب و کار شیراز» رتبه دارد):
  عنوان پیشنهادی: `میلاد بهرامی | مشاور کسب‌وکار و سیستم‌سازی سازمانی در شیراز`
  توضیحات: `مشاوره کسب‌وکار، عارضه‌یابی و سیستم‌سازی سازمانی؛ طراحی فرآیند، BPMS و ERP متناسب با DNA کسب‌وکار شما. حضوری در شیراز و آنلاین در سراسر ایران.`
  (کلمه‌ی کلیدی فعلی «مشاور کسب و کار» + «شیراز» حفظ می‌شود؛ ادعای «بهترین… +95%» حذف می‌شود.)
- حذف meta description تکراری قبلی (از قالب Phlox بود؛ با قالب جدید خودکار حذف می‌شود).
- دو دسته‌ی بدون description: توضیح بنویسید.

## مرحله ۵ — اجرا روی سایت اصلی
زمان پیشنهادی: کم‌ترافیک‌ترین ساعت (طبق Analytics). حدود ۳۰ دقیقه.
1. پشتیبان تازه (مرحله ۰).
2. تکرار مرحله ۲ (بندهای ۲ تا ۱۱) روی سایت اصلی — با خروجی تازه‌ی المنتور از سایت اصلی.
3. آروان‌کلاد → Purge کامل کش.
4. `python3 scripts/seo_snapshot.py https://thisismbahrami.ir docs/live-after.csv --paths-from docs/baseline-live-2026-09-25.csv` و `--compare`.
5. Search Console → ارسال مجدد `sitemap_index.xml` + URL Inspection برای صفحه‌ی اصلی و ۵ صفحه‌ی مهم.
6. افزونه‌ی `MB Migration` بعد از یک هفته پایداری حذف شود.

## بازگردانی (در هر لحظه)
- سریع: پوسته‌ها → فعال‌سازی Phlox Pro؛ فعال‌سازی Elementor/Pro/Auxin؛ ابزارها → مهاجرت قالب → **بازگردانی کامل**؛ Purge کش آروان.
- کامل: DirectAdmin → Restore از پشتیبان مرحله ۰.

## پایش ۴ هفته‌ای بعد از انتشار
- Search Console: Pages (خطای 404/Soft 404)، Core Web Vitals، کوئری‌های اصلی («مشاور کسب و کار»، «مشاور کسب و کار شیراز»، «قیف فروش»، «سلطان قیف»).
- هفته‌ی اول روزانه، بعد هفتگی. افت بیش از ۲۰٪ در کلیک‌های یک صفحه → بررسی همان صفحه.
